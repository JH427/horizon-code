01 / From request to verified answer

The agent owns execution; the model proposes actions.
01 · INPUT
TUI or headlessPrompt + retained conversation + hierarchical HORIZON.md + capability policy.
02 · ROUTE
Optional THXChoose request-scoped reasoning settings. At most two decisions per turn.
03 · GENERATE
Qwen via llama.cppStream reasoning, answer text, telemetry, and fragmented native tool calls.
04 · EXECUTE
Typed tool registryValidate JSON; read/search/edit/patch files or run authorized bounded commands.
05 · CHECK
Verification gateMutation requires a successful approved build/test/static check before completion.
06 · FINISH
Answer + journalAccept completion only when verification is satisfied and background work is quiescent.

Feedback loop: tool results return to Qwen for inspection, implementation, and repair. Verification failures keep the turn open; budgets and cancellation bound the loop. Every emitted decision, tool result, and accepted answer is recorded in private JSONL.

02 / Runtime boundaries

Small components; explicit ownership; no invisible model execution.
Process + model lifecycle

Owned Qwen, external THX

  • Launch the configured llama.cpp server; wait for /health and verify the model identity.
  • Refuse to claim an already healthy server. Stop the owned process group on exit.
  • THX must already be serving loopback HTTP. Horizon never installs, starts, or owns the sidecar.
  • Ordinary tests/builds use fakes—not real inference.
State + observability

Conversation is live; journals are durable

  • Retain messages and tool evidence across turns in-process; no automatic disk-session restore.
  • Compact older complete tool rounds while retaining the request and recent evidence. Active context budget: 48K tokens.
  • Record failures, probabilities, phases, selected lanes, latency, and truncation. Recording failure cancels the turn.
  • TUI shows stream/tool activity, decode speed, RAM, and system-wide AMD VRAM/GTT—not model-only GPU usage.

03 / THX-01: a compute allocator, not a second coding agent

Off → no calls · Shadow → record only · Active → apply bounded overrides
Three typed questions / one request

What THX predicts

  • Choice: A deliberate, B fast, C uncertain; distribution over all three.
  • Score: task complexity from 0 (lookup) to 3 (complex consequential work).
  • Noul: probability that fulfilling the request requires mutation or state-changing execution.

THX is non-autoregressive: it classifies compact state rather than writing code. Native extraction/citation capabilities are not currently wired into the agent.

Two bounded decision points

Read the actual task before reallocating

  • Turn start: original request, capability, verification status, prior tool outcome, and context pressure.
  • Before step 3: one reclassification using successful reads from the first two steps, only if no mutation occurred.
  • Prioritize task/spec excerpts; strip tool formatting and omit oversized fixture lines. Caps: 1,200 bytes/task, 256/other, 1,800 total.

The second decision replaces—not compounds—the first allocation. Missing reads do not reopen the window later.

Deterministic controls outrank predictions

Fallback and repair stay predictable

  • Strict response validation; loopback-only unauthenticated HTTP; redirects disabled; default deadline 2 seconds.
  • Timeout, malformed output, or explicit abstention preserves normal defaults, unless repair requires deliberate compute.
  • Tool failure or pending-verification recovery selects deliberate reasoning independently of sidecar availability.
  • Incomplete evidence cannot enable fast mode. THX cannot change registered tools, permissions, or verification requirements.
B / fast inspectionThinking disabled
Normal total cap: 4,096 tokens

Requires P(B) ≥ .55, both auxiliary outputs, complexity ≤ 1.5, mutation probability ≤ .4, and no truncation/abstention. Mutation or failure ends fast routing.

Normal / fixed baseline + fallbackLow effort, bounded thinking
2,048 thinking / 4,096 total

Default Qwen lane. reasoning_effort=low is an advisory prompt instruction; llama.cpp’s thinking_budget_tokens is the actual hard reasoning control.

A / selective escalation + required repairMedium effort, larger finite budget
4,096 thinking / 8,192 total

A requires P(A) ≥ .75. Uncertain C escalates at complexity ≥ 2.5 or mutation probability ≥ .9. Explicit abstention is distinct from C. Thresholds remain experimental.

04 / Safety, evidence, and operating the system

Reliable execution is the foundation; routing gains are still a hypothesis.
Capability + completion policy

Three explicit execution levels

  • safe: confined file tools and approved verification commands; default.
  • workspace: patches/path operations, structured argv execution, managed background jobs.
  • operator: adds direct shell and broader autonomy; explicitly authorized only.

Not an OS sandbox. Broad executables run with the user’s permissions. Purpose labels do not make commands read-only. All background jobs must stop before the successful verification starts.

--lock-after-verification optionally blocks further agent mutations after the first passing check and permits two 1,024-token, no-thinking finalization steps. Off by default; it is not best-artifact rollback.

# Start the external THX sidecar separately.
bin/horizon-code \
  --workspace /path/to/repo \
  --capability workspace \
  --decision-mode active \
  --decision-checkpoint doofz/THX-01 \
  --decision-url http://127.0.0.1:8001 \
  --decision-timeout 2s

Default launcher: ~/.config/horizon-llm/run-server.sh. Add --prompt for headless work. Sessions live under ~/.local/state/horizon-code/sessions/ or the XDG state directory.
